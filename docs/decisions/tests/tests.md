## TS-2 コンポーネントの中にある挙動の扱い：リセットは関数に出し、ほかは E2E で確かめる

- 決めたこと：
  - TW Palette Generator の、入力の色からスライダーの起点（色相・明度・彩度を丸めた値）とパレットと BASE を計算する処理を、`adjustments.ts` の `getBaseState` に出した。コンポーネントは、色の入力の後（100ms の遅延の後）にこれを呼んで結果を入れるだけにした。あわせて、コンポーネントの起点の値（`baseHue`・`baseLightness`・`baseSaturation`・`basePalette` の4つの state）を1つの state（`base`、型 `SliderBase`）にまとめ、「調整をリセット」は `getResetState(inputColor, base)` を呼ぶだけにした。スライダーの処理は `base.hue` などを読むように書き換えただけで、計算は変えていない（レビューの必須の指摘と親の判断による）
  - 単体テストの期待値は実装から作らない：起点の値は liblab の画面に出た値（`#3ba0be` で 221・66・13。phase-4/tools.md の E7）と、liblab の初期値（`#0ea5e9` で 237・68・19）、パレットは liblab の出力（`tests/fixtures/tw-palette-generator/expected.json`）
  - 次の挙動はコンポーネントの中にあり、`node:test` からは呼べないので、ブロック2の E2E で確かめる
    - Favicon Generator：選んだ出力形式の分だけファイルが出ること（単体テストの `generate()` は、コンポーネントの「選んだ形式ごとに `generateOutputSet` を呼んでつなぐ」処理をテストの側で書き直したもので、コンポーネントのその処理自体は確かめていない）、生成したファイルが1つならそのファイル、2つ以上なら `favicons.zip` にすること、サイズを小さい順に並べること、出力形式を選ばないとダウンロードできないこと
    - TW Palette Generator：スライダーの値から「起点との差」を出して `adjustColor`・`adjustPalette` に渡すこと、リセットの結果がスライダー・パレット・BASE に入ること（`setTargetHue` などの呼び忘れは単体テストでは見つけられない）、履歴の保存（30件まで）・削除・全削除・`localStorage` からの読み込み
    - SVG Optimizer：スイッチを手で変えるとプリセットの選択が外れること
- 根拠：リセットは、テストの側でコンポーネントの計算を写すと、コンポーネントを壊しても通るテストになっていた（レビューの必須の指摘）。履歴やスライダーの差の計算も関数に出せるが、既存の挙動を変えずに手を入れる前に守るテストが要り、それが E2E になるので、E2E で直接確かめる
- 手で確かめたこと（変更の前に守る E2E がまだないため）：`astro preview` をブラウザペインで開き、JS で操作して確かめた。開いた直後のスライダーは 237・68・19。入力欄に `3ba0be` を入れると 221・66・13 になる。色相を 120 にすると BASE とパレットが変わり、「調整をリセット」で 221・66・13、BASE `#3BA0BE` に戻る。`ef4444` を入れると 25・64・27 になり、パレットは Tailwind の red と同じになる。明度を 30 にしたあとのリセットで、スライダー・BASE・パレットの11段がすべて元に戻る
- 他の選択肢：4つの state を残し、`getBaseState` の結果をそれぞれに入れる（`handleReset` で値を取り違える書き方が残る）。履歴の操作やスライダーの差の計算も関数に出す
- 戻すときの作業：`getBaseState`・`SliderBase` を消し、コンポーネントの state と効果の処理を前の形に戻し、テスト（`the input color sets where the sliders start` と reset のテスト）を直す

## TS-3 確認待ちの挙動はテストしていない

- 解決済み（fixes2 の A）：FX-1 の `removeDesc`：オンにしたとき、空でもエディターのものでもない `<desc>` が消えないこと（`removeAny`）は、ユーザーの確認待ちのためテストしていない。`removeDesc` のオンは、エディターが書いた `<desc>`（`Created with ...`）が消えることだけを見る。オフで残ることは FX-1 で直した挙動として見る

## TS-4 ブロック1で見つけた、仕様として決まっていない挙動（直していない。親に判断してほしい）

テストを書く中で見つけた。どれも liblab からの既存の挙動で、6 を除き、今の挙動を固定するテストは書いていない。

2026-10-21 にユーザーが判断し、6つとも `fixes2` で対応した（各項目の「解決済み」。修正後の挙動を正としてテストする）。

1. SVG Optimizer の「小数点以下の桁数」（`floatPrecision`）は、`cleanupNumericValues` が丸める数値（`r`、`width` など）にしか効かない。パスデータ（`convertPathData`）と値のリスト（`cleanupListOfValues`。`x`・`y`・`points`・`viewBox` など）は、svgo の既定の3桁のままになる。たとえば「最大圧縮」（1桁）でもパスの座標は3桁、0 にしても3桁、5 にしても3桁に丸められる。画面の文言は「小数点以下の桁数」なので、利用者はパスにも効くと受け取りうる。直すなら svgo の設定の `floatPrecision`（全プラグインに効く）を渡すか、該当プラグインに個別に渡す（出力が変わるので `expected.json` を作り直す）
   - 解決済み（fixes2 の B）：パスデータと値のリストにも効くようにした。`floatPrecision sets the decimal places of lists of values`、`floatPrecision sets the decimal places of path data` で確かめる
2. SVG Optimizer の `removeRasterImages` は、`xlink:href` で埋め込んだ画像しか消さない（svgo のプラグインの仕様）。SVG 2 の `href` で書いた `<image>` は「最大圧縮」でも残る
   - 解決済み（fixes2 の C）：`href` の PNG・JPEG・GIF も消すようにした。`removeRasterImages on makes its change, off does not`（`href`）と `removeRasterImages removes PNG, JPEG and GIF images by href or xlink:href` で確かめる
3. SVG Optimizer の「transform属性の精度」（`transformPrecision`）は、`translate` などの桁数には効くが、`rotate` の角度は svgo が3桁までに抑える（`degPrecision`）
   - 解決済み（fixes2 の D）：角度（`rotate`・`skewX`・`skewY`）にも効くようにした。`transformPrecision sets the decimal places of angles` で確かめる
4. TW Palette Generator の入力欄は、16進数の後ろに別の文字が続く入力（`12345g`、`0x1234`）を色として受け付け、パレットを作る（`hexToRgb` の `parseInt` が先頭の読める部分だけを読むため。`12345g` は `#012345` になる）。6文字や3文字の長さの確認はしている
   - 解決済み（fixes2 の F）：3桁か6桁の16進数だけを受け付けるようにした。`input that is not a color gives no palette`（単体）と E2E の `input that is not a color leaves the palette as it was` で確かめる
5. TW Palette Generator の明度スライダーを一番下まで下げても、真っ黒（`#000000`）にはならず、色味がわずかに残る（`#3ba0be` で `#000005`）。一番上では `#FFFFFF` になる
   - 解決済み（fixes2 の G）：明度が 0 なら `#000000` にした。`at lightness 0 the color is black`、`above lightness 0 the lightness slider works as before`、`the lightness slider at 0 makes BASE black`（単体）と、同じ名前の E2E で確かめる
6. SVG Optimizer のプリセット「標準圧縮」（ID は `svgo-default`、コメントは「SVGO's actual default preset」）の中身は、svgo 4.1.0 の実際の `preset-default` と違う。`removeTitle`・`removeViewBox` がオン（svgo 4 の `preset-default` には入っていない）、`sortAttrs` がオフ（svgo 4 の `preset-default` には入っている）。画面の名前は「標準圧縮 / Standard Compression」なので不具合とは言い切れない。テストは今の中身を「標準圧縮」として確かめ、テスト名で「SVGO default」とは呼んでいない
   - 解決済み（fixes2 の H）：ユーザーの判断で中身は変えず、コードのコメントを実際の中身に合わせて直した

## TS-5 E2E の組み立て（ブロック2）

- 決めたこと：
  - `@playwright/test`（1.64.1、Apache-2.0。ユーザー承認済み）を devDependencies に足した。ブラウザは Chromium だけ（`npx playwright install chromium`。ブラウザはユーザーのキャッシュ（`%LOCALAPPDATA%\ms-playwright`）に入り、リポジトリには入らない）
  - 設定は `playwright.config.js`、テストは `tests/e2e/*.spec.js`、共通の処理は `tests/e2e/helpers.js`。`npm test` の `tests/**/*.test.js` には当たらない名前にした。テストは既存と同じく JS で書き、文言は `src/tools/messages/{ja,en}.ts` と `src/messages/layout.ts` から読む（文言を変えてもテストを直さずに済み、日英の両方を同じテストで回せる）
  - 配信は計画の第一案の `wrangler dev`（ポート 8788）。Playwright の `webServer` が起動し、終わると止める。`_redirects`・`_headers` も本番と同じ仕組みで効く
  - `npm run test:e2e` は `astro build && playwright test`。古い `dist/` に対して走らないよう、毎回ビルドする（`astro check` は `npm run build` に任せて省いた）。CI では `npm run build` の後にもう一度ビルドすることになる
  - 再試行（`retries`）は 0。不安定なテストを、2回目に通ったことで見逃さないため
  - 失敗したテストのトレースとスクリーンショットを `test-results/` に、HTML のレポートを `playwright-report/` に出す（ブロック4で成果物にする）。どちらも `.gitignore` と ESLint の対象外に足した
  - ページを開いたら、React の island の水和（`astro-island` の `ssr` 属性が消える）を待ってから操作する（`helpers.js` の `open`）。待たないと、水和の前のクリックが効かずに落ちた
  - ファイルの投入は `<input type="file">` に `setInputFiles`、ドラッグ&ドロップは `DataTransfer` を作って `dragenter`（オーバーレイが出ることを確かめる）と `drop` を送る。ダウンロードは Playwright の `download` イベントで受け取り、中身（ICO の各画像、ZIP の中身、PNG の寸法と画素）を `sharp`・`jszip` で読む。テスト用の画像は `sharp` でその場で作る
  - クリップボードはコンテキストに `clipboard-read`・`clipboard-write` を許可して `navigator.clipboard.readText()` で読む。Windows では改行が CRLF で戻るので、Tailwind Config の比較の前に LF にそろえる
  - 横スクロールは、`<html>` の横スクロールに加えて、レイアウトの外側の `div`（`overflow-x-hidden` ではみ出しを隠している）の `scrollWidth` も見る（`<html>` だけでは、はみ出しが隠れて見つからない）
  - 配色は、テーマ切替ボタンでライトとダークを選び、代表的な要素の計算後の色を比べる（ダークでは背景が暗く、文字が明るくなる）。Tailwind v4 の色は `oklch()` で返るので、ページの中で canvas に塗って RGB にし、相対輝度で比べる（`helpers.js` の `luminance`）。色の値そのものは固定しない
- 他の選択肢：`astro preview` で配信する（`_redirects` が効かない）。`test:e2e` ではビルドせず、`dist/` があることだけを確かめる（CI の二重ビルドは避けられるが、古いビルドを試験しうる）。TS で書く
- 戻すときの作業：`playwright.config.js`、`tests/e2e/`、`package.json` の `test:e2e` と `@playwright/test`、`.gitignore`・`eslint.config.js` の追加分を消す

## I3 テストの後にプロセスが残らないこと

- `npm run test:e2e` と `npx playwright test` の後に、`wrangler`・`workerd`・Playwright の Chromium のプロセスがないこと、ポート 8788 で待ち受けているものがないことを、PowerShell（`Get-CimInstance Win32_Process`、`Get-NetTCPConnection`）で確かめた（Windows）。サーバーは Playwright の `webServer` が起動して止めるので、テストの側で止める処理は持たない
- 自動のテストにはしていない（Playwright はすべてのテストと `globalTeardown` の後にサーバーを止めるので、テストの中からは確かめられない）。CI（Linux）では、ジョブの終わりにランナーごと捨てられる

## TS-9 GitHub Actions のワークフロー（ブロック4）

- 決めたこと：
  - `.github/workflows/test.yml`（ワークフロー名 `Test`）に、ジョブを1つ（ID・名前とも `test`）置いた。**ブランチ保護で必須にするチェックの名前は `test`**（GitHub の画面では「Test / test」と並ぶことがある）
  - 起動は `push`（全ブランチ）と `pull_request`。`permissions` は `contents: read` だけ。シークレットは使わない。`actions/checkout` は `persist-credentials: false`
  - 使う Action は公式の4つで、リリースのタグが指すコミットの SHA で固定した。SHA は `gh api repos/actions/<名前>/releases/latest` のタグ名から `git/ref/tags/<タグ>` を引き（4つとも軽量タグで、指す先は commit）、`commits/<タグ>` でも同じ SHA になることを確かめた（2026-10-21）
    - `actions/checkout` v7.0.1 `3d3c42e5aac5ba805825da76410c181273ba90b1`
    - `actions/setup-node` v7.1.0 `949feb2413d6458794dcd2491c4babbbce0c15c1`
    - `actions/cache` v6.1.0 `55cc8345863c7cc4c66a329aec7e433d2d1c52a9`
    - `actions/upload-artifact` v7.0.2 `cf430e030ddbb5b0abf93d22962f4752f3646cd9`
  - 手順：`npm ci` → `npm run build` → `npm run lint` → `npm run format:check` → `npm test` → `npx playwright test`。ビルドは1回で、単体テストと E2E が同じ `dist/` を使う（親の判断。`npm run test:e2e` は使わない）。Node は `.node-version` から読み、npm のキャッシュは `setup-node` の `cache: npm`
  - Playwright のブラウザは `~/.cache/ms-playwright` を `actions/cache` でキャッシュする。キーは OS と Playwright の版（`npx playwright --version` から取る）。キャッシュがないときは `npx playwright install --with-deps chromium`、あるときはシステムのライブラリだけ `npx playwright install-deps chromium` で入れる
  - E2E の配信は、ローカルと同じ `playwright.config.js` の `webServer`（`wrangler dev`）。`WRANGLER_SEND_METRICS=false` を渡す
  - どこかの手順が失敗したら、`playwright-report/` と `test-results/`（トレース・スクリーンショット）を成果物 `playwright-results` として14日残す（ファイルがなければ何もしない）
  - 上の条件（起動、手順と順序、Chromium だけ、読み取りだけの権限、シークレットなし、`actions/*` を SHA で固定）は `tests/workflow.test.js` がファイルの文面で確かめる。ワークフローを書き換えて条件を外れたら `npm test` が落ちる（条件を1つずつ壊して落ちることを確かめた）

- 未検証：GitHub 上での実行（親が push して確かめる）。とくに、Linux のランナーで `wrangler dev`（`workerd`）が起動すること、`npm ci` の時点で `workerd`・`esbuild` の install スクリプトが動くこと（ローカルの npm は「allowScripts で許可されていない install スクリプトがある」と警告を出すが、ローカルでは `wrangler dev` は動いている）
