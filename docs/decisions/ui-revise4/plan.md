## ユーザーの指示と親の解釈

### 1. ヒーロー

1. ロゴシンボルを撤去する
2. タイトル「昼はカフェ。夜はバー。」を `text-2xl` にする
3. BOOTH と GitHub へのリンクをテキストボタンにする。次の3パターンを並べて比べられるようにする
   - A：ロゴ＋テキスト
   - B：テキスト＋斜め矢印（↗）
   - C：テキスト＋リンクのアイコン
   - GitHub のロゴは、以前フッターで使っていた公式のマーク（削除した `src/components/icons/GitHubIcon.astro`。git の履歴から戻す）。BOOTH は公式ロゴの改変が認められていないので、公式ロゴは使わず、汎用の「お店」のアイコン（Heroicons の building-storefront など）を使う
   - **比較の作り方（親の判断）：** 本番のコードには入れない。プレビュー用の worktree（`%TEMP%\claude\me-preview`）に、このブランチの最新から作るローカルブランチ `mock/hero-buttons` で、見本ページ `/mock/hero-buttons` を作る（ヒーローを3パターン並べたもの。noindex）。本番のヒーローは、ユーザーが選ぶまで仮に B にしておく

### 2. カードエリア

1. **ホバーのアニメーションを統一する。** 親の判断：全カード（写真のカード、大きなカード、リスト型）で、liblab と同じ「背景色が変わる」動き（150ms、ライトは gray-100、ダークは atom-one-dark-light）に揃える。写真の拡大と浮き上がりはやめる（third-party の画像の著作権表示が切れる問題もなくなる。`thirdPartyImage` の扱いは不要になるなら整理してよい）
2. **Libraries、Apps、VR & 3D は詳細（モーダル）をやめる。** カード全体のクリックで直接飛ぶ。行き先：Apps はツールのページ、Libraries はドキュメント（なければ npm または PyPI）、VR & 3D は BOOTH の商品ページ。カードに出す操作のリンクは、行き先が2つ以上ある場合（Libraries のドキュメントと npm など）だけ残す。DIY Keyboards は今までどおり詳細を開く
3. **年を削除する**（全カテゴリ、カードと詳細の両方）
4. **VR & 3D のサブ分類のタグ（アバター / アセット / Unityツール）を削除する。** 表示をやめる。データ上のサブ分類は残してよい（表示しないなら型と一緒に整理してもよい。判断ログに書く）
5. **ダミーの商品を削除する。** VR & 3D は実際の商品（ムルル対応ツール）だけになる。リリース前チェックリストの「ダミーの BOOTH 商品と画像を本物に差し替える」は、残りの商品を足すことに意味が変わる（親が直す）
6. **リンクのアイコンは斜め矢印（↗）にする。** 「>」（シェブロン）はやめる。DIY Keyboards の「詳しく見る」はリンクではなく詳細を開くボタンなので、矢印を付けない
7. **Apps のテキストを liblab と同じにする。** liblab のツールカードに出ていた文言（ツール名と、カードに表示していた説明文）をそのまま使う。どの文言をカードに出していたかは liblab のソースで確かめる

### 3. フッター

4列のグリッドにし、比率を 2:1:1 にする（ブランドと説明文が2列、Links が1列、残りのグループ（支援・プライバシーポリシーなど）が1列）。セルの中は左寄せ。幅が狭いときの積み方は liblab に合わせる。
