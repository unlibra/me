# Phase 4 判断ログ（親）

## P4-1 MIT 側のコードの置き場所を `src/tools/` と `src/components/ui/` に固定する

- 決めたこと：WEBツールの実装コードは `src/tools/**`、共通UI部品は `src/components/ui/**` に置き、この2つを MIT の範囲とする。MIT 側から All rights reserved 側を import することを ESLint で禁止する
- 根拠：設計書 3.7 で MIT の範囲は「WEBツールの実装コード」と「UI部品」と決まっているが、ディレクトリまでは決まっていない。Phase 5 で `LICENSE` に範囲を書くので、ここで固定する。import を一方向に限ると、MIT 側だけを取り出しても動くことが構造で保証され、ライセンスの境界がコードの依存関係と一致する
- 他の選択肢：ファイルごとに SPDX ヘッダーを付けて範囲を示す（REUSE 方式）。ディレクトリで分けるほうが単純
- 戻すときの作業：ディレクトリを移し、ESLint のルールを外す

## P4-2 ツールの機能は変えずに移植する

- 決めたこと：移植で変えるのは Next.js と Tailwind v3 に依存する部分だけで、ツールの機能・生成結果・保存キーは liblab と同じにする
- 根拠：設計書 3.4 は「残す」とだけ決めている。機能の変更はユーザーの判断が要る
- 戻すときの作業：—

## P4-3 ツール一覧ページには、ツールのカードだけを置く

- 決めたこと：`/lab` と `/en/lab` はツールのカードの一覧にする。liblab のトップにあった紹介文（「すべて無料、すべてオープンソース」など）と支援セクションは載せない
- 根拠：紹介文は新しいサイトの位置づけ（サイト全体は All rights reserved、ツールは MIT）と合わない文面を含み、書き直すと画面の文言を新たに決めることになる。最終UIチェックで、一覧ページに紹介文を置くかを確認してもらう
- 戻すときの作業：一覧ページに文言を足す

## P4-4 `tsconfig.json` の `baseUrl` を外し、`src/...` 形式の import を構造的に使えなくする

- 決めたこと：Block 1 のレビューで、`baseUrl: "."` のせいで `import ... from "src/config/site"` がリポジトリのファイルに解決され、ライセンス境界の ESLint ルールをすり抜けると分かった。`baseUrl` を外してこの書き方自体を解決できなくし、加えてルール側でも `src` などリポジトリ直下のディレクトリで始まる指定子をローカルとして判定する
- 根拠：ルールの穴を塞ぐだけだと、別の抜け道が見つかるたびに直すことになる。書き方そのものを使えなくするほうが確実（safe-by-construction）。`@/*` の別名は `baseUrl` がなくても使える
- 他の選択肢：ルールの修正だけで済ませる
- 戻すときの作業：`tsconfig.json` に1行戻す
