# Phase 1 判断ログ（親）

## P1-1 Cloudflare Web Analytics はダッシュボードの自動設定で入れ、コードに計測タグを書かない

- 決めたこと：計測用の JS スニペットはサイトに埋め込まない。`unlibra.com` は Cloudflare のプロキシを通しているので、Web Analytics の自動設定（プロキシしているサイトでは既定で有効）で計測タグを挿入させる
- 根拠：Cloudflare の公式手順では、プロキシしているサイトは自動設定が既定。コードもトークンの管理も要らない
- 他の選択肢：トークン付きの JS スニペットを手動で埋め込む
- 注意：Workers の静的配信を独自ドメインで出す場合に自動挿入が効くかは、公式ドキュメントに記載がない。Phase 6 でドメインを付け替えた後に確認し、効かなければ手動スニペットに切り替える
- 戻すときの作業：レイアウトにスニペットを1つ足し、トークンを定数に置く

## P1-2 404 ページを Phase 1 で用意する

- 決めたこと：最小限の `404.astro` を作り、Workers の `not_found_handling` を `404-page` にする。文言は日英併記
- 根拠：設計書 3.2 で廃止したイロマイドの URL は404にすると決めており、Workers の既定の404より自前のページのほうが自然。ツールは日英あるが404ページは1つしか置けないので併記にする
- 他の選択肢：Workers 既定の404のまま
- 戻すときの作業：ページを消し、設定を1行戻す

## P1-3 Worker の名前を `unlibra-com` にする

- 決めたこと：`wrangler.jsonc` の `name` を `unlibra-com` にする
- 根拠：まだデプロイしていないので、Workers Builds を接続する前なら自由に変えられる
- 戻すときの作業：設定を1行変える

## P1-4 `/sitemap.xml` から `/sitemap-index.xml` への301は Phase 6 で入れる

- 決めたこと：静的ファイル版の `public/sitemap.xml` を削除し、robots.txt は `/sitemap-index.xml` を指す。Search Console などに `/sitemap.xml` が登録されている場合に備えて、Phase 6 の `_redirects` で `/sitemap.xml` → `/sitemap-index.xml` の301を足す
- 根拠：リダイレクトは Phase 6 でまとめて書くことになっている
- 戻すときの作業：静的ファイルを戻す

## P1-5 テストは `node:test` で書く

- 決めたこと：テストフレームワークは追加せず、Node 標準の `node:test` でビルド結果を検証する
- 根拠：既存のテストがなく、Phase 1 で確かめるのはビルド結果のファイルなので、標準機能で足りる
- 他の選択肢：Vitest を入れる。Phase 4 で React コンポーネントの単体テストが必要になったら、そのときに検討する
- 戻すときの作業：テストファイルを移す
